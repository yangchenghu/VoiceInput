# macOS 极简语音输入工具开发说明

版本：v1.0  
日期：2026-10-12  
状态：需求与方案已确认，尚未开始实现  
暂定名称：轻语（可在创建项目时修改）

## 1. 项目目标

开发个人使用的 macOS 语音输入工具：按住快捷键说话，松开后将语音转为文字，可选轻度纠错，最终输入到当前应用的输入框。

核心目标按优先级排列：

1. 不修改用户剪贴板。用户复制的网址在语音输入后仍可直接粘贴。
2. 操作简单，优先保证 Cursor 内的日常输入体验。
3. 尽可能缩短说完到文字出现的时间。
4. 功能保持克制，不扩展成 AI 助手。

本项目独立实现，使用服务商官方 API；不依赖闪电说客户端、会员接口或其实现代码。

| 项目 | 决定 |

### 2.1 第一版不做

- 屏幕截图、读屏理解、Agent、技能、知识库或长期记忆。
- 账号系统、订阅收费、云端同步。
- 语音翻译、扩写、总结、风格重写。
- 多家语音服务同时适配、本地语音模型。
- 持久化录音历史、复杂转写历史管理。
- Windows、iOS、真正注册到系统输入源的 InputMethodKit 输入法。

上述项目不进入本期排期。菜单栏工具即可实现本期交互目标。

## 3. 用户流程

### 3.1 首次使用

1. 打开应用，显示简洁的设置或引导窗口。
2. 配置豆包官方语音服务凭证，提供官方控制台或文档入口。
3. 引导用户授予麦克风权限，以及快捷键监听和文字输入实现实际需要的辅助功能／输入监控权限。
4. 确认快捷键和录音模式。
5. 可选开启轻度纠错并配置文本模型。
6. 用户在 Cursor 中放置光标，开始语音输入。

不申请屏幕录制权限，不默认读取屏幕或周围文本。正式实现前核实各系统 API 的实际权限要求，避免索取无关权限。

### 3.2 默认：按住录音

1. 用户按下右 Command。
2. 胶囊进入录音状态，麦克风开始采集；建立语音服务连接，并尽早发送音频。
3. 按住期间持续录音、上传和接收中间识别结果。
4. 松开右 Command，停止采集并发送协议要求的结束标记。
5. 等待最终识别结果；启用纠错时再进行轻度纠错。
6. 确认修饰键已释放、目标应用与焦点条件安全，再输入文字。
7. 胶囊短暂显示完成后消失。

用户感觉是“松开后识别并出字”，实际实现必须边录音边识别，而不是松开后才上传完整录音。

### 3.3 可选：点击切换

1. 单独按下并松开快捷键，开始录音。
2. 再次单独按下并松开，结束录音。
3. 后续识别、纠错和输入流程与按住模式相同。

两种模式通过设置选择，避免同时启用导致歧义。

### 3.4 取消

- 录音、转写或纠错期间按 Esc，取消本次任务。
- 胶囊也提供取消按钮。
- 取消后停止麦克风、关闭本次连接并取消后续请求。
- 已取消任务的迟到结果不得输入。
- 空音频或最终空文本直接结束，不输出占位文字。

## 4. 快捷键行为

### 4.1 默认右 Command

必须区分左右 Command，不将左 Command 当作默认录音键。

右 Command 是修饰键，单独使用与组合键之间存在判定窗口。原则是正常键盘操作优先：

- 右 Command + C / V / Tab / 其他键必须继续作为正常组合键工作。
- 按住录音模式中，按下右 Command 可先启动短暂的候选录音；一旦检测到其他按键构成组合键，立即取消候选／当前录音，不提交文字，不触发纠错。
- 候选期间音频是否先缓存在本地、何时开始网络上传，应在技术验证后决定；短暂缓冲可以减少正常组合键产生的无效请求。
- 不吞掉原有 Command 组合键事件，不让自己的合成输入再次触发录音。
- 点击切换模式中，只有未参与组合键的完整按下／松开才算一次点击。
- 点击切换模式录音期间使用 Command+C 等快捷键，不应被误判成停止录音。
- 过滤系统自动重复事件和抖动，避免重复开始或重复停止。
- 设置窗口正在录制新快捷键时，暂停正常快捷键响应。

单修饰键全局监听是首个技术验证项。不能仅凭普通快捷键库声称支持右 Command，必须实机验证。

### 4.2 自定义

设置页提供快捷键录制控件、当前绑定说明和恢复默认按钮。

- 至少支持右 Command 以及常用带修饰键的组合键。
- 支持范围以可靠实现为准，不承诺所有硬件键或系统保留键都可绑定。
- 对可检测的冲突和不可用组合给出明确提示。
- 若无法检测跨应用冲突，应提供测试提示，不能显示“保证无冲突”。

## 5. 底部胶囊

### 5.1 展示规则

- 工作时出现，空闲时隐藏。
- 放在开始录音时目标应用所在屏幕的可用区域底部中央，避开 Dock。
- 不激活应用、不抢走 Cursor 或其他输入框焦点。
- 多显示器、不同缩放比例、全屏应用和 Space 切换需要实测。
- 视觉简洁：圆角胶囊、清晰状态文字、小型动态波形或加载动画。
- 不依赖屏幕录制权限。

### 5.2 状态内容

| 状态 | 显示 | 行为 |
| --- | --- | --- |
| 准备中 | 正在连接… | 仅当连接延迟可感知时显示，已采集音频有限缓冲 |
| 录音中 | 红点、波形、已录时长，例如 00:08 | 支持 Esc 或按钮取消 |
| 转写中 | 加载动画、正在转写… | 等待最终结果，不继续录音 |
| 纠错中 | 加载动画、正在轻度纠错… | 仅在纠错开启时显示 |
| 输入中 | 正在输入… | 较长文本输入时可见 |
| 完成 | 已发送输入 或 已完成 | 短暂显示后隐藏 |
| 失败／暂停输入 | 简短原因、重试或打开结果入口 | 不自动消失导致内容丢失 |

不使用虚假百分比。录音展示时长，转写和纠错展示阶段及不定进度动画。

无法验证目标控件收到完整文本时，完成提示不要宣称“已验证输入成功”。

## 6. 语音识别

### 6.1 服务商

第一版仅接入豆包官方流式语音识别。

开始实现时必须阅读当时最新官方文档，确认：

- 对应账号产品的 WebSocket 地址、区域和资源标识。
- 新版 API Key 或 App ID / Access Token 等鉴权方式。
- 音频编码、声道、采样率和推荐分片大小。
- 消息头、序列号、压缩、结束帧以及最终结果语义。
- 中间结果是覆盖还是增量，避免重复拼接。
- 单次时长、并发、计费、超时和错误码规则。

不得将未核实的历史接口或模型名称硬编码为已验证配置。

### 6.2 音频与连接

- 采用原生音频采集；按官方要求转换为目标格式。
- 按协议建议分片发送，录音与网络发送不阻塞主线程或音频回调。
- WebSocket 建立期间允许有限内存缓冲，禁止无界积压。
- 明确连接超时、结果超时、最大录音时长及缓冲上限。
- 识别最终结果才可提交输入，中间结果不直接写入用户编辑器。
- 处理麦克风不可用、耳机切换、设备格式变化、休眠与断网。
- 第一版设备变化可取消本次录音并提示重新开始，无需复杂无缝切换。
- 失败时可将本次音频暂存在内存，供用户明确点击重试；设置有界大小和生命周期，取消、完成、新任务替换或退出后释放。
- 无可重试音频时明确提示重新录音，不显示无法实现的重试按钮。

### 6.3 延迟目标

核心度量：松开快捷键至首次文字输出、至全部文字输出的时间。

以下为设计目标，尚未实测，不是对云服务的承诺：

- 录音视觉反馈尽量在 100 ms 内出现；首次系统权限提示单独处理。
- 网络正常、短句、纠错关闭时，争取松开后约 1 秒开始输出。
- 流式识别优先，避免录完后再上传。
- 纠错增加的延迟单独统计，并设置有界超时。
- 不以后台持续开启麦克风换取速度。

必须用实际录音与实际服务商账号记录延迟分布，不能只用模拟接口宣称达到指标。

## 7. 轻度纠错

### 7.1 行为

提供开关。建议首装默认关闭，以便先验证原始识别效果与速度；用户需要时开启。

允许：

- 修正明显错别字和确定的同音误识别。
- 补充必要标点，保留合理的中英文混排。
- 修复确定的专有名词拼写。

禁止：

- 扩写、总结、翻译或改变语气。
- 擅自增加信息、删除事实、改动数字与单位。
- 把疑似网址、路径、代码、命令或标识符改写成自然语言。
- 执行转写文本里的指令或回答其中的问题。

### 7.2 模型配置

第一版采用一个经过实测的文本模型适配，配置项为 HTTPS Base URL、API Key、模型名称。优先实现常见 Chat Completions 兼容接口，但必须明确“兼容”不代表任意服务商都能直接使用。

具体文本模型未在本轮确定，不默认复用语音 API Key。可以选择豆包文本模型，但其开通、端点和凭证应单独核实。

提示词原则：将转写内容作为待编辑数据，明确要求只返回纠正后的文本，不返回解释或 Markdown 包装。建议低随机性配置；不要依赖提示词提供绝对正确保证。

纠错失败、返回空文本、超时或输出明显异常时，回退到原始转写，不阻断输入。初始超时可设为约 2 秒，按实测调整。

不逐 token 输入纠错结果；等整段结果确定后提交，避免用户编辑器出现难以撤销的半成品。

## 8. 文字输入与剪贴板

### 8.1 默认：Unicode 键盘事件

使用 macOS 合成键盘事件携带 Unicode 文本，发送给前台目标应用，不通过剪贴板传输文字。

- 对 Unicode 按合法边界分片，不能拆坏 UTF-16 代理对；验证 emoji、中文、组合字符与长文本。
- 在快捷键修饰键全部释放后输入，避免合成文字被解释为 Command 快捷键。
- 检查目标应用未变化；可获取辅助功能焦点时记录并比较目标元素。
- 录音开始后若前台应用或已知焦点发生变化，暂停自动输入，将结果保留在应用内，提示用户重新定位后明确输入。
- 不自动激活旧窗口，不把文字强行发回用户已离开的应用。
- 对无法识别的焦点，不宣称能够百分之百检测同应用内输入框切换。
- 不检测或读取用户剪贴板来实现该模式；验收要求内容与 changeCount 都不因语音输入改变。
- 不自动回退到剪贴板模式。

多行文本尤其需要验证：不能通过盲目合成 Return 键实现换行，否则可能在聊天框触发发送。无法保证安全输入的文本保留为结果供用户处理。

### 8.2 手动启用：兼容粘贴模式

设置页明确说明该模式会临时使用剪贴板。只有用户主动选择后才可启用。

1. 在实际粘贴前保存剪贴板当前内容，保留多个 item 及可读取的类型数据。
2. 写入本次文本，记录自身写入对应的 changeCount。
3. 向正确的目标发送粘贴快捷键。
4. 经过经目标应用验证的读取窗口后，如果剪贴板仍是自身写入的版本，恢复保存内容。
5. 若期间用户或其他应用更新剪贴板，不恢复旧快照覆盖新内容。

保存时机必须是粘贴前，而非录音开始时，以保留录音期间新复制的网址。

剪贴板存在延迟提供、无法读取的类型和跨进程时序问题，不能保证所有内容无损保存。快照失败时应停止兼容粘贴并提示，不直接覆盖。恢复时的检查和写入不是系统级原子事务，应明确仍有极短竞争窗口。应用崩溃也可能阻止恢复。因此此模式是兼容选项，不能替代默认无剪贴板模式的保证。

### 8.3 失败后的结果

仅在内存保留最近一次结果，直到新任务替换或退出。

- 用户可查看结果并主动重试输入。
- 提供显式“复制结果”按钮；点击它才会有意修改剪贴板。
- 输入结果无法确认时不自动再次输入，以免重复。
- 不在后台静默创建转写历史文件。

## 9. 设置与菜单

### 9.1 设置页

采用单窗口、少量分组，不做复杂导航。

| 分组 | 项目 |
| --- | --- |
| 输入操作 | 快捷键录制、恢复默认、按住／点击模式 |
| 语音识别 | 豆包凭证及必要资源配置、默认系统麦克风说明或简单设备选择、连接测试 |
| 轻度纠错 | 开关、Base URL、模型名称、密钥、测试 |
| 文字输入 | 默认无剪贴板模式／兼容粘贴模式及说明 |
| 权限 | 麦克风及实际需要的系统权限状态、打开系统设置 |

敏感信息默认遮罩。凭证检查不能只判断文本非空；联网测试说明会发送测试请求，可能产生少量费用，用户点击后才执行。

### 9.2 菜单栏

只保留：状态、打开设置、查看最近结果（存在时）、退出。

退出时取消录音和请求，不保持麦克风占用。

## 10. 状态与并发

建议状态机：

`空闲 → 准备/录音 → 等待最终转写 → 可选纠错 → 输入 → 完成 → 空闲`

任一活动阶段可进入取消或失败；焦点不安全时进入“等待用户输入结果”。

- 同一时间只有一个活动录音／处理任务。
- 每个任务有唯一 session ID，所有异步回调先核对任务仍有效。
- 第一版处理期间的新录音触发可提示“正在处理”，不启动并行任务；用户可先按 Esc 取消再开始。
- 输入提交最多一次，超时后的迟到结果不得再次提交。
- 设置修改对下一次任务生效，避免中途切换服务、凭证或输入模式。
- 关闭窗口不等于退出；取消、退出、权限撤销与设备断开都有明确资源清理路径。

## 11. 建议技术实现

以下为设计建议，正式建项目时按 SDK 与验证结果调整：

- Swift + SwiftUI：设置和结果界面。
- AppKit：菜单栏、非激活悬浮 NSPanel、窗口生命周期。
- AVAudioEngine / AVAudioConverter：采集与格式转换。
- URLSessionWebSocketTask：语音识别连接。
- URLSession：纠错请求。
- Core Graphics 事件能力：全局按键监听与 Unicode 合成输入，重点验证右侧修饰键。
- Keychain：API 凭证；UserDefaults：非敏感偏好。
- XCTest：协议解析、状态机、异步取消、文本分片等关键逻辑。

建议最低系统先以 macOS 14 为候选，最终由项目实际使用 API 决定并在 README 标明。首期验证 arm64；没有 Intel 真机测试前，不宣称兼容已验证。

不要默认启用与全局事件能力冲突的 App Sandbox 配置。发布第一阶段采用用户本机自建／运行；如果以后对外分发，再处理稳定签名、公证与分发渠道。不要为个人原型引入账号或更新服务器。

### 11.1 模块边界

| 模块 | 职责 |
| --- | --- |
| AppCoordinator | 生命周期与单任务状态机 |
| HotkeyService | 快捷键监听、模式、自定义与组合键判定 |
| AudioCaptureService | 音频采集、格式转换、有界缓冲 |
| DoubaoStreamingASR | 官方协议、网络连接、结果解析 |
| CorrectionService | 可选文本纠错、超时与回退 |
| TextInsertionService | Unicode 输入、目标校验、手动兼容模式 |
| OverlayController | 胶囊窗口和状态展示 |
| SettingsStore / CredentialStore | 普通配置与凭证隔离 |

保留语音识别服务和文字输入策略的接口边界，避免过度抽象成插件系统。

## 12. 数据与隐私

- 云端语音识别会将录音发送至用户配置的豆包服务。
- 开启纠错会将转写文本发送至配置的文本模型服务。
- 不发送剪贴板内容、屏幕截图或当前文件内容。
- 凭证不进入仓库、UserDefaults、普通日志或崩溃报告。
- 日志默认只记录状态、耗时、错误类别及经过脱敏的请求标识；不记录音频、转写全文、Authorization 或带密钥 URL。
- 本次录音和结果仅在内存中有界保留，用于处理与明确重试。
- 如未来新增诊断导出，必须由用户主动触发并说明内容。

## 13. 开发顺序

### 阶段 A：先验证高风险交互

先做两个最小实验，不急于接云端或打磨界面：

1. 右 Command 的按下／松开监听、左右区分，以及正常 Command+C / V / Tab 不被破坏。
2. 不使用剪贴板向 Cursor 输入固定测试文本：中文、英文、标点、emoji、选区替换、多行与长文本。

若 Cursor 的 Unicode 输入兼容性不满足需求，记录具体失败情形，与用户重新评估输入路线，不静默改成粘贴板方案。

### 阶段 B：打通主链路

菜单栏、设置、权限、录音、豆包流式识别、胶囊、默认无剪贴板输入。先关闭纠错。

### 阶段 C：补充已确定功能

轻度纠错、点击切换录音、自定义快捷键、失败结果保留、用户手动兼容粘贴模式。

### 阶段 D：实机验收

Cursor 优先，再验证备忘录、浏览器普通输入框和微信。完成错误路径、网络、设备和多屏测试；记录兼容性及限制。

## 14. 验收标准

### 14.1 核心场景（必须通过）

1. 复制网址，切到 Cursor，按住右 Command 说话，松开后出现文字；随后 Command+V 仍粘贴原网址。
2. 默认模式整个流程中剪贴板内容和 changeCount 均保持不变。
3. 录音期间复制另一个网址，语音输入后仍可粘贴这个新网址。
4. 右 Command+C / V / Tab 正常，不产生意外语音文本；左 Command 不触发默认录音。
5. 按住模式和点击切换模式都可正常开始、结束、取消。
6. 自定义快捷键保存后生效，重启后保留，恢复默认有效。
7. 胶囊在正确屏幕出现，不夺取 Cursor 焦点；显示时长、转写、纠错与错误状态。
8. 关闭纠错只调用 ASR；开启后保持原意，超时回退原转写。
9. Esc 取消后即使网络结果迟到也不输入。
10. 语音输入不自动发送聊天消息。
11. 前台应用变化时暂停自动输入，不把文字输入到新应用。
12. 处理失败时能看到原因，并按条件重试或查看最近结果。

### 14.2 关键边界

- 麦克风／辅助功能权限拒绝或撤销。
- 无效凭证、额度不足、断网、WebSocket 异常关闭、结果超时。
- 连续多次录音、极短录音、静音、长录音、快速重复按键。
- 中文英文混排、emoji、网址、代码片段、多行文本、选区替换。
- 蓝牙耳机切换、麦克风断开、系统休眠恢复。
- 多屏、全屏、不同缩放、输入时切换 Space。
- 安全输入或受限输入框无法写入时给出可理解的回退，不尝试绕过系统保护。
- 兼容粘贴模式测试纯文本、网址、图片、多类型剪贴板和粘贴期间新复制内容；记录无法保证的情况。

### 14.3 自动化测试重点

只写能捕获实际风险的测试：

- 协议帧和最终／中间结果解析、错误帧与结束语义。
- 取消、超时、重试和迟到回调不会重复输入。
- Unicode 分片不破坏字符。
- 纠错失败回退原文本。
- 剪贴板恢复策略在 changeCount 变化后不覆盖新内容。
- 快捷键状态转换和组合键排除。

云端实测、真实键盘事件、Cursor 编辑器行为与系统权限不能仅用单元测试代替。

## 16. 尚待实现阶段验证的决定

这些事项不阻止创建项目，但不能假装已完成验证：

## 17. 可直接用于新项目的开发任务

请依据本说明开发一个个人使用的 macOS 菜单栏语音输入工具。先阅读仓库指引并检查开发环境，然后完成阶段 A 的右 Command 和 Cursor 无剪贴板输入技术验证，再实现豆包流式识别及后续功能。默认按住右 Command 录音、松开结束，保留点击切换模式与自定义快捷键；屏幕底部显示不抢焦点的胶囊；轻度纠错可关闭；默认不读写用户剪贴板来传输文字，不自动回退粘贴模式，不自动发送消息。使用官方 API，密钥由用户在本机设置页填写并安全保存。严格区分已实现、模拟测试通过、真实服务验证通过及仍需用户验证的部分，遇到核心交互不可行时先说明证据，不静默改变已确认需求。
